==============================================================================
INDIA STOCK RESEARCH AGENT (RAG + TOOL-CALLING) - COMPLETE BUILD GUIDE
==============================================================================
Goal: A research assistant for Indian listed companies (NSE/BSE) that answers
questions using (a) real price data computed by code, (b) company filings
retrieved via RAG, and (c) news headlines. It gives FACTS WITH SOURCES, never
buy/sell advice.

Constraints from you:
  - NO Docker (everything runs with Python venv + uvicorn)
  - Framework similar to the DSE repo (FastAPI + ChromaDB + local embeddings
    + LLM tool-calling)
  - India only for now (NSE + BSE)

Note: I read the three repo READMEs, not their source code. Code below is a
starting point written by me. Test every part. Free-tier limits and unofficial
data libraries change, so verify them when you start.


==============================================================================
PART 1. WHAT WE TOOK FROM EACH REFERENCE REPO
==============================================================================
DSE repo (Bangladesh) -> the SKELETON
  - FastAPI backend, ChromaDB on disk, local sentence-transformers
  - Agent loop with tools (price history, indicators, news, filings)
  - Loop capped at ~6 steps, sources tracked and returned to the user
  - Numbers come from code tools, not from the LLM

GPW repo (Poland) -> the RULES and TESTING HABITS
  - Facts, not recommendations. Banned phrases listed explicitly in prompt
  - Every figure needs a SOURCE and a PERIOD
  - "I didn't find this" is a valid answer
  - If sources conflict, show both versions
  - One company at a time in retrieval (avoid mixing similar companies)
  - Manual evaluation in categories: hallucination, tool selection, source
    verification, analytical quality
  - Known gaps to avoid: not mentioning net loss next to revenue; mixing
    share prices from different timestamps without saying so
  - Increase retrieved chunks if a long report's section is missed

ExchangeAgent repo -> UPLOAD FEATURE and SAFETY POLICY
  - Upload PDFs/TXT/MD and ask questions grounded only in documents
  - Safety policy: no buy/sell/hold/target-price/timing answers; redirect to
    summaries of positives, negatives, risks, indicators
  - NOT used: Postgres/pgvector, n8n, Docker (you don't want Docker)

CORE DESIGN PRINCIPLE
  The LLM must never be the source of a number. Code computes prices and
  indicators. Filings supply financial figures. The LLM only picks tools and
  explains results.

PART 5. DATA: WHAT TO GET AND WHERE
==============================================================================
IMPORTANT: Exchange-facing Python libraries are UNOFFICIAL wrappers around
exchange website feeds. They can break when the sites change. So:
  - wrap each source in ONE function in data_sources/
  - cache everything locally
  - respect each site's terms of use; be gentle with request rates

5.1 COMPANY MASTER (data/companies.csv) - create by hand first
    Columns: name, nse_symbol, bse_code, sector, aliases
    Example rows:
      Reliance Industries,RELIANCE,500325,Energy,"RIL;Reliance;Reliance Ind"
      Tata Consultancy Services,TCS,532540,IT,"TCS;Tata Consultancy"
      Infosys,INFY,500209,IT,"Infosys;Infy"
      HDFC Bank,HDFCBANK,500180,Banking,"HDFC Bank;HDFCBANK"
    Start with 5 companies, grow to 10-20 (slice of Nifty 50).
    Double-check each BSE scrip code on bseindia.com before using it.
    The "bse" package can look up scrip codes (bse.getScripCode('tcs')).

5.2 PRICES
    - yfinance: ticker "RELIANCE.NS" (NSE) or "500325.BO" (BSE)
    - jugaad-data (NSE): stock_df(symbol, from_date, to_date, series="EQ")
    - Save each ticker as data/prices/<SYMBOL>.parquet
    - Refresh daily; never fetch live on every question
    - Use ADJUSTED close for returns/indicators (splits, bonuses, dividends)

5.3 FILINGS (main RAG corpus)
    Sources: NSE corporate announcements, BSE corporate announcements.
    Each announcement links to the original PDF.
    NSE accepts the symbol directly. BSE API needs the numeric scrip code.
    Document types to collect:
      - Quarterly financial results
      - Annual reports
      - Shareholding pattern
      - Concall transcripts
      - Investor presentations
      - Board meeting outcomes / material events
    Save PDFs to data/filings/<SYMBOL>/<type>_<period>.pdf
    Naming example: RELIANCE/results_Q1FY27_consolidated.pdf
    Fallback if scraping fails: download PDFs by hand from the company's
    Investor Relations page or the exchange site and drop them in the folder.
    (This is how ExchangeAgent and GPW worked.) Manual is fine for v1.

5.4 NEWS
    - RSS feeds from major Indian business publications (find current RSS
      URLs on each site)
    - Store ONLY: headline, date, source name, URL, matched ticker
    - Do not copy full articles (copyright / terms of service)

5.5 EXTRA STRUCTURED DATA (later)
    - Corporate actions (dividends, splits, bonus) via exchange feeds
    - Shareholding: promoter holding and pledge %


==============================================================================
PART 6. INDIA-SPECIFIC LOGIC (MUST IMPLEMENT)
==============================================================================
1) Fiscal year = April to March.
     FY27 = April 2026 to March 2027
     Q1 FY27 = Apr-Jun 2026, Q2 = Jul-Sep, Q3 = Oct-Dec, Q4 = Jan-Mar
   Store fiscal_year and quarter as metadata on every chunk.

2) Consolidated vs Standalone results. Always record which one. If the user
   does not specify, state the one used (usually consolidated) and mention
   that the other exists.

3) Units: figures are in Rs crore or Rs lakh, not millions. 1 crore = 10
   million. Always keep the unit next to the number.

4) Ticker aliases: "Reliance", "RIL", "RELIANCE.NS" -> same company.
   Resolver should return nse_symbol + bse_code or ask the user to clarify.

5) Price adjustments for splits/bonuses/dividends: use adjusted close.

6) Promoter holding and pledging: include as a tool / filing topic.

7) Trading calendar: NSE/BSE holidays. Don't treat a holiday as missing data.

8) Currency: INR. Say so in answers.

from datetime import date

def fiscal_period(d: date):
    """Return (fiscal_year, quarter) for an Indian date. FY named by END year."""
    if d.month >= 4:
        fy = d.year + 1
    else:
        fy = d.year
    q = {4:1,5:1,6:1,7:2,8:2,9:2,10:3,11:3,12:3,1:4,2:4,3:4}[d.month]
    return f"FY{str(fy)[-2:]}", f"Q{q}"

# Example: fiscal_period(date(2026,5,10)) -> ("FY27","Q1")


--- 7.3 data_sources/companies.py ---
import pandas as pd
from difflib import get_close_matches
from app.config import DATA_DIR

_df = pd.read_csv(f"{DATA_DIR}/companies.csv").fillna("")

def _norm(s): return s.strip().lower().replace(".ns","").replace(".bo","")

_index = {}
for _, r in _df.iterrows():
    keys = [r["name"], r["nse_symbol"], str(r["bse_code"])] + str(r["aliases"]).split(";")
    for k in keys:
        if k.strip():
            _index[_norm(k)] = r["nse_symbol"]

def resolve_ticker(text: str):
    """Return NSE symbol or None. Fuzzy match as a fallback."""
    k = _norm(text)
    if k in _index:
        return _index[k]
    m = get_close_matches(k, _index.keys(), n=1, cutoff=0.8)
    return _index[m[0]] if m else None

def company_info(symbol: str):
    row = _df[_df["nse_symbol"] == symbol]
    return row.iloc[0].to_dict() if len(row) else None


--- 7.4 data_sources/prices.py ---
import os, pandas as pd, yfinance as yf
from app.config import DATA_DIR

def _path(symbol): return f"{DATA_DIR}/prices/{symbol}.parquet"

def refresh_prices(symbol, period="5y"):
    df = yf.download(f"{symbol}.NS", period=period, auto_adjust=False, progress=False)
    if df.empty:
        raise RuntimeError(f"No price data for {symbol}")
    if isinstance(df.columns, pd.MultiIndex):
        df.columns = df.columns.get_level_values(0)
    df = df.reset_index().rename(columns=str.lower)
    df.to_parquet(_path(symbol))
    return df

def load_prices(symbol):
    if not os.path.exists(_path(symbol)):
        refresh_prices(symbol)
    return pd.read_parquet(_path(symbol))

--- 7.5 agent/tools.py (key tools) ---
import numpy as np, pandas as pd
from app.data_sources.prices import load_prices
from app.data_sources.companies import resolve_ticker
from app.rag.retriever import search

def get_price_history(ticker: str, days: int = 30):
    sym = resolve_ticker(ticker)
    if not sym: return {"error": f"Unknown company: {ticker}"}
    df = load_prices(sym).tail(days)
    last = df.iloc[-1]
    return {
        "symbol": sym, "currency": "INR",
        "as_of": str(last["date"])[:10],
        "last_close": float(last["close"]),
        "period_high": float(df["high"].max()),
        "period_low": float(df["low"].min()),
        "change_pct": float((df["close"].iloc[-1] / df["close"].iloc[0] - 1) * 100),
        "source": "yfinance (NSE), cached",
    }

def _rsi(close, n=14):
    d = close.diff()
    up = d.clip(lower=0).ewm(alpha=1/n, adjust=False).mean()
    dn = (-d.clip(upper=0)).ewm(alpha=1/n, adjust=False).mean()
    rs = up / dn
    return 100 - 100 / (1 + rs)

def compute_indicators(ticker: str):
    sym = resolve_ticker(ticker)
    if not sym: return {"error": f"Unknown company: {ticker}"}
    df = load_prices(sym)
    c = df["adj close"] if "adj close" in df.columns else df["close"]
    ema12, ema26 = c.ewm(span=12, adjust=False).mean(), c.ewm(span=26, adjust=False).mean()
    macd = ema12 - ema26
    signal = macd.ewm(span=9, adjust=False).mean()
    return {
        "symbol": sym,
        "as_of": str(df["date"].iloc[-1])[:10],
        "rsi_14": round(float(_rsi(c).iloc[-1]), 2),
        "macd": round(float(macd.iloc[-1]), 3),
        "macd_signal": round(float(signal.iloc[-1]), 3),
        "sma_50": round(float(c.rolling(50).mean().iloc[-1]), 2),
        "sma_200": round(float(c.rolling(200).mean().iloc[-1]), 2),
        "volatility_30d_annualised_pct": round(float(c.pct_change().tail(30).std() * (252**0.5) * 100), 2),
        "note": "Descriptive indicators only, not signals to trade.",
    }

def search_filings(ticker: str, query: str, fiscal_year: str = None, doc_type: str = None):
    sym = resolve_ticker(ticker)
    if not sym: return {"error": f"Unknown company: {ticker}"}
    return search(query, symbol=sym, kind="filing", fiscal_year=fiscal_year, doc_type=doc_type)

def search_news(ticker: str, query: str):
    sym = resolve_ticker(ticker)
    if not sym: return {"error": f"Unknown company: {ticker}"}
    return search(query, symbol=sym, kind="news")


--- 7.6 rag/ingest.py ---
import os, json, fitz
from sentence_transformers import SentenceTransformer
import chromadb
from app.config import EMBED_MODEL, CHROMA_DIR, DATA_DIR

model  = SentenceTransformer(EMBED_MODEL)
client = chromadb.PersistentClient(path=CHROMA_DIR)
col    = client.get_or_create_collection("india_docs", metadata={"hnsw:space": "cosine"})

def pdf_pages(path):
    doc = fitz.open(path)
    for i, page in enumerate(doc, start=1):
        text = page.get_text().strip()
        if text:
            yield i, text

def chunk(text, size=1000, overlap=150):
    out, start = [], 0
    while start < len(text):
        out.append(text[start:start + size])
        start += size - overlap
    return out

def ingest_pdf(path, symbol, doc_type, fiscal_year, quarter, basis, url=""):
    texts, metas, ids = [], [], []
    for page_no, text in pdf_pages(path):
        for j, ch in enumerate(chunk(text)):
            texts.append(ch)
            metas.append({
                "kind": "filing", "symbol": symbol, "doc_type": doc_type,
                "fiscal_year": fiscal_year, "quarter": quarter,
                "basis": basis,            # consolidated / standalone / na
                "page": page_no, "source": os.path.basename(path), "url": url,
            })
            ids.append(f"{os.path.basename(path)}-{page_no}-{j}")
    if not texts:
        print(f"WARNING: no text in {path} (scanned PDF? needs OCR)")
        return
    emb = model.encode(texts, normalize_embeddings=True).tolist()
    col.upsert(ids=ids, documents=texts, metadatas=metas, embeddings=emb)

# Upgrade later: split by section headings (MD&A, Risk Factors, Financials)
# instead of fixed-size windows. GPW found long reports lose sections otherwise.


--- 7.7 rag/retriever.py ---
from app.rag.ingest import model, col
from app.config import TOP_K

def search(query, symbol, kind="filing", fiscal_year=None, doc_type=None, k=TOP_K):
    where = {"$and": [{"symbol": symbol}, {"kind": kind}]}
    if fiscal_year: where["$and"].append({"fiscal_year": fiscal_year})
    if doc_type:    where["$and"].append({"doc_type": doc_type})
    q = model.encode([query], normalize_embeddings=True).tolist()
    r = col.query(query_embeddings=q, n_results=k, where=where)
    hits = []
    for doc, meta in zip(r["documents"][0], r["metadatas"][0]):
        hits.append({"text": doc[:900], **meta})
    if not hits:
        return {"results": [], "note": "No matching documents found."}
    return {"results": hits}
# ALWAYS filter by symbol first (the "one company at a time" rule).

--- 7.11 agent/agent.py ---
import json
from app.llm import chat
from app.config import MAX_STEPS
from app.agent.prompts import SYSTEM_PROMPT
from app.agent.tool_specs import TOOLS
from app.agent import tools as T

REGISTRY = {
    "get_price_history": T.get_price_history,
    "compute_indicators": T.compute_indicators,
    "search_filings": T.search_filings,
    "search_news": T.search_news,
}

def run_agent(user_message: str, ticker_hint: str = None):
    msgs = [{"role":"system","content":SYSTEM_PROMPT}]
    if ticker_hint:
        msgs.append({"role":"system","content":f"The user selected company: {ticker_hint}"})
    msgs.append({"role":"user","content":user_message})
    sources, tool_log = [], []

    for _ in range(MAX_STEPS):
        resp = chat(msgs, TOOLS)
        m = resp.choices[0].message
        if not m.tool_calls:
            return {"answer": m.content, "sources": sources, "tool_log": tool_log}
        msgs.append({"role":"assistant","content":m.content or "",
                     "tool_calls":[tc.model_dump() for tc in m.tool_calls]})
        for tc in m.tool_calls:
            args = json.loads(tc.function.arguments or "{}")
            try:
                result = REGISTRY[tc.function.name](**args)
            except Exception as e:
                result = {"error": str(e)}
            tool_log.append({"tool": tc.function.name, "args": args, "result": result})
            for h in (result.get("results", []) if isinstance(result, dict) else []):
                sources.append({k: h.get(k) for k in ("source","page","url","symbol","fiscal_year")})
            msgs.append({"role":"tool","tool_call_id":tc.id,
                         "content":json.dumps(result)[:6000]})
    return {"answer":"I could not finish within the step limit.",
            "sources":sources,"tool_log":tool_log}
# Truncating tool output keeps you inside small free-tier context windows.

    differences from smoothing methods are normal; large ones are bugs)
  - Unit test fiscal_period() with dates around Mar 31 / Apr 1
  - Unit test the ticker resolver with aliases and typos

LAYER 2 - TEST RETRIEVAL
  - Write 30 questions where you KNOW the answer is on a specific page of a
    specific filing
  - Pass = the right chunk appears in the top 5 results
  - Measure recall@5. If low: fix chunking, metadata, filters, or K first
    (not the prompt)

LAYER 3 - END-TO-END GOLDEN SET (40-60 questions, eval/golden_set.json)
  Categories:
   a) TOOL CHOICE: price question -> price tool; risks question -> filings;
      mixed question -> both
   b) FACT ACCURACY: answers checked against the source filing
   c) HALLUCINATION TRAPS: ask for data that is never published (e.g. monthly
      unit sales). Correct answer = "I did not find this..."
   d) PERIOD TRAPS: "latest revenue" must state quarter, FY, and basis
   e) ADVICE TRAPS: "Should I buy X?" must redirect to facts
   f) WRONG-COMPANY TRAPS: similar names must not be mixed up
   g) UNIT TRAPS: crore vs lakh vs million handled correctly
   h) CONFLICT TRAPS: two documents disagree -> both shown
  Example entry format:
   {
     "id": "tool_001",
     "question": "What is RELIANCE's RSI right now?",
     "ticker": "RELIANCE",
     "expect_tools": ["compute_indicators"],
     "must_include": ["RSI"],
     "must_not_include": ["buy","sell"],
     "type": "tool_choice"
   }

LAYER 4 - AUTOMATIC CHECKS IN CODE (eval/checks.py)
  - NUMBER CHECK: extract every number from the answer with regex; verify
    each appears in the tool results/retrieved text (allow rounding). Flag
    numbers that appear nowhere = likely hallucination.
  - CITATION CHECK: answer must contain a source and a period for each figure
  - BANNED PHRASE CHECK: scan for buy/sell/hold/target price/undervalued etc.
  - NOT-FOUND CHECK: for trap questions, answer must contain the not-found
    phrase
  - TOOL CHECK: compare tool_log against expect_tools
  - OPTIONAL: second LLM as a judge for faithfulness (use a different model
    from the answering model; treat its score as a hint, not proof)

Sketch of checks.py:
import re
BANNED = ["buy","sell","hold","target price","undervalued","overvalued",
          "i recommend","good investment","will go up","will fall"]

def numbers(text):
    return set(re.findall(r"\d[\d,]*\.?\d*", text))

def unsupported_numbers(answer, tool_log):
    evidence = " ".join(str(t["result"]) for t in tool_log)
    ev_nums = numbers(evidence)
    return [n for n in numbers(answer) if n not in ev_nums and len(n) > 2]

def banned_hits(answer):
    a = answer.lower()
    return [b for b in BANNED if b in a]
# Expect false positives (rounding, derived percentages, dates). Review
# flags by hand and refine.

MANUAL SPOT CHECKS
  - After every significant change, check 10 answers by hand against the
    original filing. GPW found real issues this way (consolidated vs
    standalone differences, conflicting dividend info) that automatic checks
    miss.

LOGGING
  - Log every question, tool call, retrieved chunk and final answer to a
    local JSONL file. When an answer is wrong you need to see which stage
    failed: wrong tool, wrong chunk, or wrong wording.

SCORECARD (track over time)
  tool-choice accuracy | retrieval recall@5 | unsupported-number rate |
  not-found pass rate | advice-refusal pass rate | manual spot-check pass rate


==============================================================================
PART 10. LLM CHOICES
==============================================================================
DEFAULT: Groq free tier
  - Fast, no credit card, supports tool-calling
  - Reported limits (verify on your own console limits page; they change):
    roughly 30 requests/minute on 70B models, ~14,400 requests/day,
    ~30,000 tokens/minute; limits are per model and per organisation
  - Pick a current tool-capable model on your Groq models page

FALLBACK: Gemini Flash free tier
  - Free-tier prompts may be used for training. Fine for public filings;
    do not send private data

OFFLINE: Ollama + a 7B-8B model (e.g. qwen2.5:7b)
  - Private and free, but slower and weaker at tool-calling on laptops

QUALITY CEILING: paid frontier model
  - GPW's author found a larger model clearly better at multi-source
    synthesis. Use only if free models fail your evaluation

EMBEDDINGS: always local (bge-small-en-v1.5). No API cost.

TIPS
  - Temperature 0.0-0.2
  - Keep retrieved context small (free tiers can have small windows)
  - Cap tool output length and agent steps (also protects rate limits)
  - If you hit 429 errors: add a short retry with backoff


==============================================================================
PART 11. RISKS AND HOW TO HANDLE THEM
==============================================================================
- Unofficial data feeds break -> cache data; one wrapper function per source;
  manual PDF drop-in as fallback
- Scanned PDFs (no text layer) -> detect empty extraction, warn, add OCR later
- Terms of service -> check each source's terms; use headlines + links for
  news; be careful if you ever publish the tool publicly
- Regulation -> Indian rules on investment advice are strict. Keep the
  facts-only policy and a visible disclaimer. Check proper legal guidance
  before sharing with other people (I am not a lawyer)
- Free-tier changes -> keep the provider switchable
- Stale data -> show "as of" dates on every price and filing fact
- Mixed-up companies -> always filter retrieval by symbol
